# Phase 3: Per-Name Aggregate & Reconciliation

## Overview

Turn the admitted + named frames from Phase 2 into the answer the user actually asked for: one row per **recorded dispatch name**, carrying call volume, terminal state mix, `error.code` histogram and latency — plus printed reconciliation invariants that make the residue auditable instead of hidden.

Three obligations are added to the earlier revision, because the reader now classifies more than it admits and because the pass no longer runs on the main thread: (a) the reader's own `STRUCTURAL_INVALID` class is a **named residue population** that this phase reports and reconciles without ever folding it into a call count; (b) quarantined partitions are a **labelled margin** (frames present / admitted / named-invalid, and why), never a recovery promise and never an addend of the admitted total; (c) the envelope is produced **off-thread** by the pass that reads the files, so aggregation here is a fold over frames as they are admitted — not a second materialisation, not a nested scan.

Every count quoted in this file is a snapshot taken by an independent read-only pass and re-derived at run time; none of them is a constant in code, tests, or assertions.

## Requirements

- **Functional:**
  - The production aggregation is a **streaming fold from the pass sink**: Phase 1's `readFramesIncremental(census, sink)` emits each admitted frame into `foldFrame(acc, frame)`, and `finalizeAggregate(acc)` yields one row per distinct `frame.name` with exactly the row key set the Phase 6 payload gate allowlists (`phase-06-gates-docs-and-followup.md:24`): `name`, `calls`, `frames`, `superseded`, `states`, `errors`, `latency`, `excludedLatency`, `firstSeen`, `lastSeen`, `lowerBound`. `aggregateByName(admitted: Frame[])` survives **only as a test-only convenience** over a handful of hand-built frames, implemented as `finalizeAggregate(admitted.reduce(foldFrame, emptyAccumulator()))` so the test and the production path provably share **one** folding implementation; its only permitted call sites are test files under `test/`, guarded by a source-text assertion that `aggregateByName(` appears at no call site in `src/`. **No production caller may pass it an array** — an array-shaped production signature is exactly how the whole ~240 MB `result`-bearing set ends up resident in one process, which is the failure this plan exists to avoid (`plan.md:80`).
  - Identity is the **validated composite** `(attachmentId, idempotencyKey)`, formed by Phase 2 only when both fields are present and non-blank; when that validation fails the frame is counted in `unattributedFrames`, never silently merged. This phase **consumes** Phase 2's discriminated result (`{ ok: true, key }` | `{ ok: false, reason: 'MISSING_IDENTITY_FIELD', field }`) and never rebuilds the key by concatenation — the truthy `"undefined\u0000undefined"` that raw concatenation produced is exactly the defect this consumes away (plan.md:194).
  - `frame.id` is **not** the identity and is not an input to it. It is minted at `src/main/session/invocation-ledger.ts:386-390` as `makeControlPlaneId('invocation')` (`src/shared/control-plane-contracts.ts:783-785` → `invocation-<randomUUID>`), an unrelated random value, while the composite is `(attachmentId, idempotencyKey)`. The composite is sound on its own terms: an independent read-only pass on 2026-09-17 over 1,043 entries / 19,175 parsed frames (a frames-present figure across every matched file, quarantine included — not an admitted count) measured 18,954 distinct composites against 18,954 distinct `id` values with **0** `id`s appearing under more than one `attachmentId` — so nothing here needs `id` to be correct, and no claim about `id` may be used to justify the key.
  - `calls` counts **distinct composite keys** per name; `frames` is the raw admitted frame count in that group and `superseded = frames - calls`. `superseded` is a reported population on its own and is **never added into `calls`** (compaction coalesces a composite's transitions into one frame, so duplicates are genuine transitions, not pollution).
  - Latency is computed **only** from owner-written terminal frames. A frame is excluded iff `state === 'unknown'` **or** it carries replay provenance (`error.details.reconciledByPid !== undefined`) — the union, so a future producer that writes provenance on another state is still caught. `settledAt` is the terminal timestamp and `createdAt` (declared `invocation-ledger.ts:42`) is the start; there is **no `startedAt` field** on the persisted record, and 0 of 19,175 live frames carry one (same independent pass; plan.md:182). The nearest-rank pair is `p50Ms`/`p95Ms` over the sorted sample with `count`; `count === 0` ⇒ `latency === null`, which renders `UNMEASURED`, never `{p50Ms: 0}`.
  - Each row also carries `excludedLatency` — the same union rule's population with **its own** `{ count, p50Ms, p95Ms }`. A bare excluded count is not a report: measured on the live store, the excluded replay population is p50 262,957 ms / p95 2,427,228 ms against a headline p50 13 ms / p95 3,787-3,799 ms (`plan.md:72`), so a count alone would let the panel read ~640× faster at p95 than the population it dropped. These are snapshots of a live store, re-derived at run time — an independent pass the same day measured the headline population at p50 13 ms / p95 3,714 ms over 18,892 owner-written samples, which is precisely why the number is computed, not asserted. `state === 'interrupted'` is **kept**: same-day independent passes (2026-09-17) measured **89 and 90** such frames respectively out of ~19.2 k parsed frames — snapshots of a live, growing store, re-derived at run time and never asserted as constants — every one an owner-written `EXECUTION_TIMEOUT` sample with 0 replay provenance (the provenance-bearing frames are all `unknown`), and `plan.md:72` keeps them.
  - `states` is a histogram over every observed `state` value (iterate what is present; the ledger's `InvocationState` union at `invocation-ledger.ts:16` is a display-order hint only, never an enumerated filter). `errors` is a histogram over `error.code` with `UNKNOWN_ERROR`-style fallbacks counted as-is, never remapped, and frames with no `error` contribute no bucket. **Both are published as object keys, so their key space is bounded by a vocabulary grammar** — no `/`, no `\`, nothing matching `^[A-Za-z]:` (note `C:x` has no separator yet is still a drive-relative path, so a separator check alone is not enough). Every observed value is still counted, but a value the grammar does not admit is bucketed under the fixed literal `UNRECOGNIZED`, its count summed into any existing bucket of that name and **never dropped** — a count that disappears would break the row's frame reconciliation, and hiding an unrecognised value would be the fabricated-zero failure in a new costume. This is not a display filter: it is the only thing standing between a persisted `error.code` and an object key that carries the operator's file layout to the renderer, which is exactly what shipped before the adversarial review (see `phase-04:34` and `phase-06:26`).
  - `reconcile()` returns `{ classifiedKeys, unattributedKeys, unattributedFrames, unattributedByReason, keylessFrames, compositeKeys, frames, superseded, holdsKeys, holdsFrames, lines }` and prints **two** invariants, key-level and frame-level, computed from independently accumulated terms (rows vs. the fold's key set vs. the credited-key ledger) so `holdsKeys` can actually be false — a term derived by rearranging another would make the check a tautology. **The frame-level identity does not meet that bar and this file must not pretend it does.** `frames == compositeKeys + superseded + keylessFrames` is maintained inside `foldFrame`, so it is a *construction invariant*: its value is catching a future refactor that breaks the construction, not discovering a wrong number today. The same is true of the four-bucket census partition (one if/else chain, `phase-01:36`) and of `holdsMargin`, which is preceded by a hard throw. The independent adversarial review falsified the stronger reading by showing that no path through `foldFrame`/`readAdmittedFrames` can make `holdsFrames` false, and that U15 can only falsify it by mutating an accumulator directly. Keep every assertion — they are cheap regression guards — but label each one for what it is, and keep `holdsFrames`'s terms written as the values they actually are rather than as expressions that merely look like guards. The exact counting rule, which is what makes the printed numbers close:
    ```
    frames             = keyedFrames + keylessFrames          (keyless = composite validation failed)
    keyedFrames        = compositeKeys + superseded            (duplicate frames under one valid key)
    compositeKeys      = classifiedKeys + unattributedKeys     (credited to a named row, or not)
    unattributedFrames = unattributedKeys + keylessFrames      (the plan's printed vocabulary)
    keyedFrames        = sum(rows.frames) + uncreditedKeyFrames (frames of an uncredited valid key)
    ```
    so the two printed lines are `classifiedKeys + unattributedKeys == compositeKeys` and `frames == compositeKeys + superseded + keylessFrames`. `plan.md:136`'s forms (`classifiedKeys + unattributedFrames == compositeKeys`, `frames == distinctComposites + superseded`) are the `keylessFrames === 0` case of those — true for every frame the ledger can write today, and no longer silently false by construction when a foreign line reaches admission. Two consequences are stated rather than discovered: the frame-level terms are accumulated over the admitted set, so `sum(rows.superseded)` equals the frame-level `superseded` exactly when `unattributedKeys === 0` (an uncredited key's duplicate frames are superseded at frame level but belong to no row), and `unattributedFrames` is the sum of the two named reasons, computed in `reconciliation` with its split published in `totals.unattributedByReason`, so the panel keeps the plan's vocabulary.
  - `unattributedFrames` counts admitted frames that could **not** be credited to a named row, and it must be **possible for it to be non-zero** — that is the whole point of validating the composite. The two named reasons are published under `unattributedByReason`: `MISSING_IDENTITY_FIELD` (Phase 2's composite validation returned `ok: false`; a keyless frame, which can never be `superseded`) and `MISSING_ROW_KEY` (a valid composite but an absent/blank `frame.name`, so there is no row to credit and its duplicates fall to `superseded`). **Reachability boundary, stated because it decides which fixture is legal:** a frame whose `attachmentId`/`idempotencyKey` is **absent or an empty string** is falsy, so the reader's structural rule rejects it as `STRUCTURAL_INVALID` before checksum and it never reaches `unattributed`; the reachable case is a value that is **truthy but not a non-blank string** (whitespace-only, or a non-string such as a number) [INFERENCE on the general class; the whitespace-only case is the fixture U7 drives]. Measured today: 0 frames with an absent, empty, whitespace-only or non-string identity field, and 0 with a blank `name`, across 19,175 frames (independent pass) — which is exactly why matrix row U7 must drive the **real** pipeline over a hand-authored checksum-valid line rather than hand-building an "unattributed" frame in memory.
  - `STRUCTURAL_INVALID` is the ledger's own structural rule — `!frame.id || !frame.idempotencyKey || !frame.attachmentId || frame.formatVersion !== 1` (`invocation-ledger.ts:188`) — evaluated by the reader **before** checksum, and it is a named residue class, never an admitted frame (`plan.md:191`, `plan.md:225`). Its exact home in the envelope: `totals.residue.STRUCTURAL_INVALID` and, when the frame came from a quarantine-labelled partition, `totals.quarantineMargin.framesNamedInvalid` + `.reasons[]`; it is the `namedInvalid` term of the margin identity. It appears in **no** other place — not in `reconciliation.frames`, not in `compositeKeys`, not in any row's `calls`/`frames`/`states`/`errors`/`latency`. A checksum-valid `formatVersion: 2` frame is therefore named, never counted as a real dispatch.
  - The quarantine margin is a **first-class labelled line in `totals`**, never folded into the admitted total and never presented as a recovery promise:
    ```
    totals.quarantineMargin = {
      label,               // printable line built at call time, e.g.
                           // 'quarantine margin: present N = admitted A + named-invalid I
                           //  (STRUCTURAL_INVALID n1, CHECKSUM_MISMATCH n2, …) — a margin, not a recovery promise'
      files, framesPresent, framesAdmitted, framesNamedInvalid,
      reasons: [{ class, reason?, count }]
    }
    ```
    `framesAdmitted` is a **split of** the admitted set (the intact quarantine frames are already inside `reconciliation.frames`), so no surface may add `framesAdmitted` to anything; the margin discloses, it does not accumulate. It is derived by **summing the pass result's `fileRollups`** and nothing else — `files` = count of `quarantineLike` roll-ups, `framesPresent` = Σ `frames`, `framesAdmitted` = Σ `admitted`, `framesNamedInvalid` = Σ `namedInvalid`, with `reasons[]` taken from the same pass's residue rows for those same files; no file is opened and nothing is re-scanned (`phase-01-census-and-contract-freeze.md:84`, `:188`). `reconcile()` computes `holdsMargin` = `framesPresent === framesAdmitted + framesNamedInvalid`; the numbers live once in `totals.quarantineMargin` and `holdsMargin` references them, so there is no second copy that can disagree. The margin is explicitly *not* a P1 recovery deliverable (user decision, `plan.md:64(g)`): 0 retained frames are repaired by this suite, and the label says so. Files skipped by the input ceiling are **not** margin: `fileRollups` carries one entry per file actually read, so the margin covers the read set only.
  - Every row-level count is a floor, and says so. Intrinsically: rows describe **retained** frames only — compaction coalesces a composite's transitions and prune unlinks partitions — so `calls` is a lower bound over the retention horizon for every row, not an exact historical count (`plan.md:169`). Additionally, when any short-read (`POST_CENSUS_TRUNCATE`/`VANISHED`) or `POST_CENSUS_APPEND` occurred, `lowerBound: true` is set on every row and the panel renders `calls` as `≥ N`, never as an exact count.
  - `0` is never rendered as "never dispatched". Per row, `firstSeen`/`lastSeen` = min/max `createdAt` in the group and bound the observed window; `totals.retention = { firstSeen, lastSeen, note }` states that a name absent from the row set means *no frame is retained in this store*, not that the tool was never called (`plan.md:139`). The same rule applies inside a row: an empty latency sample renders `UNMEASURED`, never `0`.
  - `reconcile()`'s margin input is the pass result's frozen **`fileRollups`** — `FileRollup = { file, quarantineLike, tempLike, frames, admitted, namedInvalid }` with the asserted per-file identity `frames === admitted + namedInvalid` (`phase-01-census-and-contract-freeze.md:72-84`, `:184`) — and this phase derives `totals.quarantineMargin` by summing it: **no file open, no re-scan**, and `reasons[]` sourced from the same pass's residue rows.
  - `totals` never restates a count that `reconciliation` already owns — the two objects are complementary, so there is exactly one number per fact: `reconciliation` owns `classifiedKeys`/`unattributed*`/`keylessFrames`/`compositeKeys`/`frames`/`superseded`/`holds*`; `totals` owns the census counts, `residue` histogram, `unattributedByReason`, `excludedLatency`, `retention` and the short-read counters. Within that, two keys are **assigned to this phase by Phase 1 / `plan.md:80`** and keep their verbatim shapes: `totals.quarantineMargin` (summed from `fileRollups`, never re-derived) and `totals.truncation = { ceiling, filesRead, filesSkipped, order }` with its `partial: N of M files` label and the covered window (oldest/newest `mtimeMs` among files read) (`phase-01-census-and-contract-freeze.md:188`, `:300`).
  - Short-read, ceiling, drift and budget handling all land in the same envelope key set, so no surface branches on the reason to decide whether a payload is well-formed:
    - `CENSUS_DRIFT` (content changed at equal size/mtime) ⇒ `status: 'UNMEASURED'`, `reasonCode: 'CENSUS_DRIFT'`, `rows: []`, `totals: null`, `reconciliation: null`; the census that detected the drift is still published. Fail closed: no partial row set.
    - `POST_CENSUS_TRUNCATE` (fewer lines than the census recorded), `VANISHED` (file gone) and `POST_CENSUS_APPEND` ⇒ rows render with `lowerBound: true` on every row, and the counts are disclosed in `totals` under the short-read counters.
    - `READ_BUDGET_EXCEEDED` (worker budget expired) ⇒ the same `UNMEASURED` shape as `CENSUS_DRIFT`: the partial fold is **discarded**, never published as a partial envelope. An **input** ceiling is the opposite case and is **not** `UNMEASURED` — the files actually read are a legitimate measurement, so rows render over the **newest-first** selection (`mtimeMs` descending, `name` ascending as the tie-break; a name-sorted prefix would render every late-sorting tool as "never called") with every row `lowerBound: true`, `totals.truncation = { ceiling, filesRead, filesSkipped, order }`, its `partial: N of M files` label and the covered window (oldest/newest `mtimeMs` among files read); only the degenerate `filesRead === 0` case is `UNMEASURED`/`POPULATION_TRUNCATED`, and the margin then covers nothing rather than pretending to cover the store (`plan.md:80`). The covered window's container and field name are **Phase 1's to freeze** (it owns the `Truncation` type); this phase renders them verbatim and never recomputes them from `stat` calls of its own. Both reason codes are members of the closed `UnmeasuredReason` enum owned by Phase 1 (`plan.md:60`); this phase consumes them and never inlines a string literal, and the ceiling is named by the pass in `limits`/`affected`, never restated here as a number.
  - `asOf` is **injected**, travels in the envelope as the snapshot time of the pass that produced it, and is **not** part of the memo key: the memo key is `sha256(sorted(name:size:mtimeMs))`, owned by Phase 4 (`plan.md:60`). This phase consumes the memo only as an optional input to `accountStore` and never reads the clock to derive `asOf`.
  - `evidenceRefs` contains only synthetic identifiers matching Phase 1's frozen `/^census:[0-9a-f]{8,}#L\d+$/` (`phase-01-census-and-contract-freeze.md:193`; `plan.md:74`). No store path, partition name, frame field, URL or absolute path enters it.
- **Non-functional:**
  - Pure functions over plain data: no filesystem access, no `electron` import, no global state, so `test/unit/mcp-dispatch-aggregate.test.ts` can drive `foldFrame`/`finalizeAggregate`/`reconcile` with hand-built frames from `.compiled`. `aggregateByName` is a **test-only** wrapper over exactly those; the production pass never builds a frame array — the sink plus `foldFrame` is the only shape it uses, and a source-text assertion keeps every `aggregateByName(` call site inside `test/`.
  - **Cost discipline, matching the off-thread architecture:** aggregation is the **finalize stage of Phase 1's `runCensusPass`** (`phase-01-census-and-contract-freeze.md:294`) and shares that pass's thread — a single in-memory fold over frames as they are admitted, inside the `node:worker_threads` pass (`plan.md:60`, `plan.md:80`), never a separate walk on the Electron main thread. After folding, no frame object — and no `result`/`authoritySnapshot` payload — is retained; the accumulator keeps only per-name state/error maps, the latency sample, `firstSeen`/`lastSeen` and the `lowerBound` flag. There is **no nested scan** (no per-row re-walk of the admitted set) and no second materialisation of the frame set on the main thread; the main process only memoizes and projects the finished envelope.
  - Deterministic ordering: rows sorted by `calls` desc, then `name` asc; histogram keys sorted for stable serialisation, so two runs of the same snapshot are byte-identical.
  - No percentage or rate is emitted that mixes two populations with different denominators, and no percentage is emitted over a population whose total is a `lowerBound` floor — that would be false precision (`plan.md:41`).
  - No file, frame, partition or capability count is hard-coded anywhere: not in the module, not in the tests, not in the assertions. Every expected value in the matrix below is computed from the fixture the test itself built.

## Architecture

```
admitted frames, streamed from the sink in Phase 1's runCensusPass / Phase 2 read (same thread, in the worker)
        │   foldFrame(): one pass, no frame retained, no nested scan
        ▼
  +--------------------------------+       residue entries (class, reason?, file)
  | per-name accumulator:          |───────────────┐
  | calls/frames/superseded,       |               │
  | states, errors, latency sample,|               ▼
  | firstSeen/lastSeen, lowerBound |   reconcile(acc, residue, fileRollups)
  +--------------------------------+               │
        │                                          ▼
        └──► rows (calls desc, name asc) + keys / frame / margin invariants
                                                   │
                                                   ▼
        envelope { status, reasonCode, affected, evidenceRefs, asOf, storePath,
                   census, fileRollups, rows, totals, reconciliation }
        built in the worker; the main process memoizes it (key = sha256(sorted(name:size:mtimeMs)),
        `asOf` NOT in the key) and projects it. READ_BUDGET_EXCEEDED / CENSUS_DRIFT arrive through
        this same key set as UNMEASURED; an input ceiling renders newest-first rows, all lowerBound, with totals.truncation (filesRead === 0 ⇒ UNMEASURED).

Frame identity            : VALIDATED composite (attachmentId, idempotencyKey) — a frame is attributed
                            only when both are present and non-blank; NOT frame.id (minted
                            `invocation-ledger.ts:386-390` as makeControlPlaneId('invocation')), and
                            never the file name
Row key                   : frame.name  (declared `invocation-ledger.ts:25`; the ledger copies the
                            post-alias name at `:394`, rewritten through aliasMap at `mcp-server.ts:675`)
Latency pair              : settledAt − createdAt  (declared `:42`; there is no `startedAt`)
Excluded-from-latency     : state === 'unknown'  OR  replay provenance present (union); `interrupted` KEPT
Superseded population     : >1 frame sharing one composite key → counted, never summed into `calls`
STRUCTURAL_INVALID        : residue class (`:188`), evaluated before checksum, never admitted
Quarantine margin         : totals.quarantineMargin.label — a labelled split of retained frames,
                            never a recovery promise and never an addend of the admitted total
```

Why the recorded name and not the caller's alias: `src/main/mcp/mcp-server.ts:675` rewrites the caller's tool name through `aliasMap` (declared `:566`) before the frame exists, and the ledger persists that rewritten value in `name` (`:394`). The typed alias is recorded nowhere; the payload states this as a named limitation instead of implying alias-corrected accounting. The row set is **not** alias-free: `antifan_switch_tab` 2 beside `browser.switch-tab` 787, `browser.eval` 1 beside `anti.browser.evaluate` 9,040, and separator variants (`browser.find` 13 / `browser_find` 5 / `browser_press_key` 17) all coexist, so **one capability can occupy several rows** [same-capability grouping is INFERENCE from naming plus count asymmetry; the name list is measured by distinct `frame.name` values over admitted frames, snapshot re-derived at run time — `plan.md:58`]. No identity/canonicalization layer is built, and this phase cites no capability-catalogue count.

## Implementation Steps

1. Read `src/main/session/invocation-ledger.ts:19-45` and freeze the frame type this phase consumes — the fields are exactly: `formatVersion`, `id`, `attachmentId`, `requestId`, `idempotencyKey`, `name` (the **recorded, post-alias** dispatch name), `paramDigest`, `policyDigest`, `policyVersion`, `recordedVisibility`, `state`, `dispatchStage?`, `authoritySnapshot`, `result?`, `error?` (`{code, message, details?}`), `evidence?`, `replacementAuthorityRevision?`, `artifactIds?`, `createdAt`, `settledAt?`, `checksum?`. Any field the reader persists but this phase does not consume must be listed in the type comment so a later schema change is visible. Prefer deriving the consumed type with `Pick<InvocationRecord, …>` from the ledger's own interface over restating it.
2. Implement the fold and its pure wrappers:
   - `emptyAccumulator()`, `foldFrame(acc, frame, lowerBound)` and `finalizeAggregate(acc)` are the **production pair**: the pass sink calls `foldFrame` once per emitted frame and `finalizeAggregate` once at the end, holding only counters, the composite-key `Set`, bounded residue and the roll-ups — never a frame array. `aggregateByName(admitted: Frame[])` exists **only for tests** over a handful of hand-built frames, as `finalizeAggregate(admitted.reduce(foldFrame, emptyAccumulator()))`, and a source-text assertion keeps every call site inside `test/`;
   - per name: `calls` = distinct composite keys, `frames` = raw frame count, `superseded = frames - calls`;
   - `states` = histogram over observed `state` values (do not hard-code the state list), key space bounded by the vocabulary grammar, everything else summed into `UNRECOGNIZED`;
   - `errors` = histogram over `error.code`, `UNKNOWN_ERROR`-style fallbacks counted as-is, same bounded key space and the same `UNRECOGNIZED` bucket;
   - `latency` = nearest-rank `p50Ms`/`p95Ms` plus `count` from `settledAt - createdAt` for non-excluded frames only; `null` when `count === 0`;
   - `excludedLatency` = the same triple over the union-excluded population;
   - `firstSeen`/`lastSeen` = min/max `createdAt`; `lowerBound` = whether any short-read/append was seen;
   - sort rows by `calls` desc then `name` asc.
3. Consume Phase 2's validated composite: attribute a frame to a key only on `{ ok: true, key }`; on `{ ok: false, reason: 'MISSING_IDENTITY_FIELD', field }` increment `unattributedByReason.MISSING_IDENTITY_FIELD` and `keylessFrames`. A valid key whose group has an absent/blank `name` increments `unattributedByReason.MISSING_ROW_KEY`. Never form the key here by string concatenation.
4. Implement `reconcile(agg, residue, fileRollups)`: accumulate `classifiedKeys` from the rows, `compositeKeys` from the fold's key set, `unattributedKeys` from the credited-key ledger, and the margin counts by **summing `fileRollups`** — four **independent** accumulations so `holdsKeys`/`holdsFrames`/`holdsMargin` can be false; build `lines` (two strings) and `totals.quarantineMargin.label` from those numbers at call time, never from constants. Because `fileRollups` carries one entry per file **actually read**, the margin is by construction over the read set: a file skipped by the input ceiling contributes nothing to `framesPresent` and is **never** counted as margin.
5. Implement `accountStore({ storeDir, asOf, memo })` as the single orchestration entry point: it **wraps Phase 1's `runCensusPass`** (`phase-01-census-and-contract-freeze.md:294`) and runs **in the same thread as that pass** (the worker, or the CLI's in-process mode) — aggregation is the finalize stage over the incremental frame sink plus `fileRollups`, never a separate walk on the Electron main thread (constraint G). Every consumer (service, CLI) goes through it; no consumer re-implements a step. A **time** budget expiry aborts with `UNMEASURED`/`READ_BUDGET_EXCEEDED` and the partial fold is **discarded** (no rows). An **input** ceiling is the opposite case: rows render over the files actually read — **newest-first by `mtimeMs` descending, `name` ascending as the tie-break**, because a name-sorted prefix would zero out every tool whose partitions sort late and would read as "never called" — with every row `lowerBound: true`, `totals.truncation = { ceiling, filesRead, filesSkipped, order }`, the `partial: N of M files` label, and the covered window (oldest/newest `mtimeMs` among files read); only the degenerate `filesRead === 0` case is `UNMEASURED`/`POPULATION_TRUNCATED` with `rows: []` (`plan.md:80`).
6. Short-read and ceiling handling, in one place: `CENSUS_DRIFT` ⇒ `UNMEASURED`, `rows: []`, `totals: null`. `POST_CENSUS_TRUNCATE`/`VANISHED`/`POST_CENSUS_APPEND` and an input ceiling ⇒ rows still render, every row marked `lowerBound: true`, the shortfalls disclosed as the short-read counters and `totals.truncation` respectively.
7. Emit the envelope with the fields the renderer consumes: `{ status, reasonCode, affected[], evidenceRefs[], asOf, storePath, census, fileRollups, rows, totals, reconciliation }` — `reconciliation.lines` are the same two strings the CLI and the Hub print, so a test can prove both surfaces agree, and `totals.quarantineMargin.label` is the third labelled line both surfaces print verbatim.
8. Write `test/unit/mcp-dispatch-aggregate.test.ts` with hand-built frames covering the matrix below. **Every fixture frame is constructed in the test file itself** — no fixture may be copied out of the live store into the repo (the store contains live dispatch payloads, and copying it would be data-exfiltration-by-fixture). Rows U7/U7b additionally write their fixture **lines** into a temp directory the test creates and drive `readAdmittedFrames` → fold → `reconcile`, because that is the only legal way to reach `unattributedFrames` without bypassing Phase 2's validation.
9. Run the phase gate: `npm run compile && node --test --test-force-exit ".compiled/test/unit/mcp-dispatch-aggregate.test.js"`.

## Success Criteria

- [ ] One row per recorded `frame.name`, sorted by `calls` desc then `name` asc; the row key set is exactly the Phase 6 allowlist.
- [ ] `calls` counts distinct validated composites; `superseded` is reported separately and never added to `calls`; `frame.id` is used nowhere as an identity.
- [ ] `unattributedFrames` is asserted **non-zero** by a row that drives the real pipeline, and that row's fixture is a checksum-valid line the test authored — not a hand-built frame that skips validation.
- [ ] `STRUCTURAL_INVALID` frames are never admitted: their only homes are `totals.residue.STRUCTURAL_INVALID` and the margin's `framesNamedInvalid`; no row, no `compositeKeys`, no admitted total contains them.
- [ ] Latency p50/p95 computed only from non-excluded frames; `count === 0` ⇒ `latency === null` ⇒ renders `UNMEASURED`; the excluded population is reported with its own p50/p95 beside its count.
- [ ] Both invariants computed from independently accumulated terms and printed; a seeded non-closing case yields the corresponding `holds* === false` without throwing.
- [ ] `holdsMargin` computed by **summing `fileRollups`** (never by opening or re-reading a file) and the margin `label` printed verbatim by both the CLI and the Hub, stating frames present / admitted / named-invalid and why, and stating that it is a margin rather than a recovery promise; a file skipped by the input ceiling contributes nothing to the margin.
- [ ] `POST_CENSUS_TRUNCATE`/`VANISHED`/`POST_CENSUS_APPEND` **and** an input ceiling ⇒ rows marked `lowerBound: true`; `CENSUS_DRIFT` ⇒ `UNMEASURED` with `rows === []` and `totals === null`.
- [ ] Every row carries `firstSeen`/`lastSeen`; `totals.retention` carries the horizon and the absence note, so no `0` is presented as "never dispatched".
- [ ] Empty admitted set ⇒ `status: 'UNMEASURED'` + `reasonCode` + resolved `storePath`; no `0` anywhere in the row set.
- [ ] Every `UNMEASURED` payload (time-budget `READ_BUDGET_EXCEEDED`, `CENSUS_DRIFT`, degenerate `POPULATION_TRUNCATED`) shares one key set (`rows: []`, `totals: null`, `reconciliation: null`, reason in `reasonCode`, mechanism in `affected`), while a non-degenerate **input ceiling** is `MEASURED` with rows over the newest-first read set, `totals.truncation = { ceiling, filesRead, filesSkipped, order }`, the `partial: N of M files` label, the covered window, and every row `lowerBound: true`.
- [ ] Aggregation retains no frame after folding and performs no nested scan; the production path never builds a frame array (`aggregateByName` has no call site in `src/`, source-text assertion); the module still imports no `electron` and the unit test drives it directly from `.compiled`.
- [ ] Two folds over the same hand-built test frames are deep-equal (determinism), and no count is hard-coded in the module or the test.

## Function / Interface Checklist

| Symbol | Signature | Responsibility |
|---|---|---|
| `foldFrame` | `(acc: AggregateAccumulator, frame: Frame, lowerBound: boolean) => AggregateAccumulator` | the single streaming aggregation pass; retains no frame |
| `finalizeAggregate` | `(acc: AggregateAccumulator) => AggregateResult` | sorts rows, computes nearest-rank p50/p95, `excludedLatency`, windows, `lowerBound` |
| `aggregateByName` | `(admitted: Frame[]) => AggregateResult` | **TEST-ONLY** convenience over hand-built frames (`finalizeAggregate` over `foldFrame`); permitted only in `test/`, enforced by a source-text assertion — no production caller may pass it an array |
| `reconcile` | `(agg, residue, fileRollups) => Reconciliation` | independent key/frame/margin accumulations, `unattributedByReason`, three booleans, two printable lines; the margin is summed from `fileRollups` only |
| `accountStore` | `({storeDir, asOf, memo}) => Promise<McpDispatchAccount>` | single orchestration entry point wrapping Phase 1's `runCensusPass` in the same thread; owns the time-budget, input-ceiling, drift and short-read outcomes |
| `McpDispatchAccount` | envelope type | `status`, `reasonCode`, `affected`, `evidenceRefs`, `asOf`, `storePath`, `census`, `fileRollups`, `rows`, `totals`, `reconciliation` |
| `QuarantineMargin` | `totals.quarantineMargin` type | `label`, `files`, `framesPresent`, `framesAdmitted`, `framesNamedInvalid`, `reasons[]` — summed from `fileRollups`, each roll-up satisfying `frames === admitted + namedInvalid` |

**Must not** re-implement Phase 2's composite validation, re-read a file, derive a term of an invariant by rearranging another term, or build a frame array on the production path.

## Dependency Map

```
Phase 2 (reader: census + bounded read + admission + validated composite + per-file roll-ups `fileRollups`)
        └──► Phase 3 (this): streaming fold + reconcile + accountStore  ──► envelope
                    ├──► Phase 4 creates service/IPC/CLI/Hub (consumes the envelope only,
                    │         owns the memo key sha256(sorted(name:size:mtimeMs)) with `asOf` excluded;
                    │         Phase 5 appends the CLI's `--core-attempts` section to that CLI)
                    └──► Phase 6 build gate (`check-mcp-dispatch-payload.mjs`): the frozen row and
                              totals key set is its allowlist; it reads source + a committed fixture only
                              and never joins populations
```

Hard ordering: the envelope shape must be frozen here before Phase 4 renders it; the CLI is Phase 4's artifact (Phase 5 appends its `--core-attempts` section) and is the cheapest place to prove the envelope because it runs without Electron. The retired self-report panel has no successor in this plan, so nothing downstream may be described as a panel-separation gate (`plan.md:121`).

## Risk Assessment

| Risk | Signal it broke | Pre-decided response |
|---|---|---|
| A state value appears that the code did not anticipate | rows show a state label not in the known set | `states` is a histogram over observed values, not a fixed list; unknown labels pass through unchanged |
| Latency looks plausible but comes from replay | p95 shifts with `initialize()` history, not with dispatch behaviour | union exclusion rule; publish the excluded population's own p50/p95 beside the headline numbers |
| `unattributed` is tested with a hand-built frame that skips validation | the row is green while the production path can never produce that value | U7 authors a checksum-valid fixture **line** and drives `readAdmittedFrames` → fold → `reconcile`; the assertion is non-zero, not a constant |
| A keyless frame makes the plan's literal invariant look false | a foreign line is admitted with no composite while `holdsKeys` is computed from a rearranged term | general forms printed with the `keylessFrames` term named; terms accumulated independently; U7/U8 cover both |
| A term of an invariant is derived by rearranging another | a seeded broken case still reports `holds* === true` | four independent accumulations; U8's mis-wired variant must yield `holdsFrames === false` |
| The invariant is asserted as a constant, or redefined until it passes | test green while a `holds*` is false, or the numbers change meaning | tests compare against `reconciliation.lines` and the recomputed numbers from the fixture |
| Frame counts are compared to key counts | `holds` false on a healthy store | key-level and frame-level invariants are computed and printed separately, with `superseded` and `keylessFrames` disclosed |
| The margin is read as a recovery promise or added to the admitted total | a panel total exceeds the admitted frame count | margin is a labelled disclosure with `holdsMargin`; `framesAdmitted` is a split of `reconciliation.frames`; nothing sums it |
| Aggregation materialises the frame set on the main thread | main-process stall or memory spike while the budget should have bounded the pass | the production path is the sink plus `foldFrame` (no frame array); no retained frames, no nested scan; a time-budget expiry discards the partial fold |
| A time-budget expiry renders rows, or an input ceiling is blanked | a partial fold is shown as a measurement, or a large store blanks the feature | only the **time** budget yields `UNMEASURED`/`READ_BUDGET_EXCEEDED` with no rows; an **input** ceiling is `MEASURED` over the files read with `totals.truncation` + `lowerBound` rows, and `UNMEASURED` only when `filesRead === 0`; U16 |
| The ceiling selects a name-sorted prefix | every tool whose partitions sort late renders "never called" | selection is newest-first (`mtimeMs` desc, `name` asc tie-break), `order` is published in `totals.truncation`, and the covered window (oldest/newest `mtimeMs` read) is stated (`plan.md:80`) |
| The margin is rebuilt by re-opening files or re-scanning | a second read pass appears, or the margin disagrees with the reader's roll-ups | margin = Σ `fileRollups` only (each entry satisfying `frames === admitted + namedInvalid`, one entry per file actually read); skipped files are not margin |
| A short read or an input ceiling silently lowers every count | totals shrink with unchanged residue | `POST_CENSUS_TRUNCATE`/`VANISHED`/`POST_CENSUS_APPEND` and the ceiling are classified; rows marked `lowerBound: true`; `CENSUS_DRIFT` fails closed |
| A zero row is read as tool disuse | a tool shows 0 while its frames were compacted or pruned | `firstSeen`/`lastSeen` per row + `totals.retention` horizon and absence note; empty latency renders `UNMEASURED` |
| A count is hard-coded and the live store moves | an assertion fails on a healthy store, or passes on a broken one | every number re-derived at run time; matrix expectations computed from the fixture; the plan itself records 19,096 / 19,164 / 19,215 admitted frames in three passes over one day (`plan.md:52`) |
| Live payloads leak into repo fixtures | a test fixture contains a real store path or URL | every fixture frame is constructed in the test file; no live frame is copied; `evidenceRefs` are synthetic only |
| Aggregation cost explodes on a large store | pass time far above the raw read baseline | single fold pass with maps; no nested scans; the worker budget bounds the worst case and the memo absorbs repeats |
