# Ultra Scout Report — F1GENZ_Chatbox

## Project & Directory

`E:\Work\apps\F1GENZ_Chatbox` — multi-tenant Haravan customer-support chatbox, forked from the `haravan-app-base` lifecycle template (per `docs/architecture-contracts.md` + `docs/source-extraction-map.md`). Layout: `server/` (NestJS 10 + Prisma 5 + ioredis, CommonJS, tsx dev), `client/` (React + Vite + AntD + TanStack Query embedded admin + Cloudflare Pages `functions/api/[[path]].js` proxy), `widget/chatbox.js` (6.9KB vanilla storefront widget), `server/prisma/` (3 migrations incl. pgvector), `docs/` (13 contract/runbook docs), `plans/260715-0021-haravan-chatbox-mvp/` (8-phase plan; phases 2–4 in progress, 5–8 pending), `recipes/` (8 docs-only modules), `scripts/` (verify-env, verify-build-output, scan-anti-patterns), `docker-compose.yml` (pgvector/pg17 + redis:7 local dev).

## Architecture & Role

Two layers of sharply different maturity:

**Layer 1 — Lifecycle spine (production-grade, test-covered).** `server/src/haravan/*`: OAuth login/install with hashed Redis state + per-flow nonce (`oauth-state.service.ts`), hand-rolled OIDC/JWKS verify RS256/384/512 + kid-refresh (`oidc-verifier.service.ts`), raw-query launch HMAC ±300s timestamp + dual decoded/raw candidate messages (`hmac-verifier.service.ts`), one-time handoff → HS256 HttpOnly cookie (`session.service.ts`), AES-256-GCM token vault (`token-encryption.service.ts`), webhook pipeline raw-body HMAC → topic normalize → identity cross-check → deterministic idempotency → inline reducer (`webhook.service.ts`, `webhook-topic-normalizer.ts`), pre-install subscription snapshots (`subscription.service.ts`), uninstall tombstones + lifecycleGeneration guard (`uninstall.service.ts`), owner-token Redis locks (`lifecycle-lock.service.ts`, `redis.service.ts` getDel/setNx/Lua release). `server/test/lifecycle.test.ts` (706 lines) covers the flow.

**Layer 2 — Chat product (MVP, partial).** `sync.service.ts` mirrors products/variants/images + orders/items + customers into Prisma; products dual-indexed into pgvector knowledge. `public-chat.controller.ts` serves `POST /api/public/chat` (origin allowlist → per-IP rate limit → domain→shop resolve → embedding top-3 → FAQ `contains` fallback → optional LLM rephrase → `{reply, source, links, results}`) and `POST /api/public/leads`. `knowledge.service.ts`: sanitize→chunk(1200c)→embed→store, sha256 dedupe, doc-partitioned cosine query. `llm.service.ts`: thin OpenAI-compatible client (DeepSeek-style `enable_thinking:false`). Admin pages: overview/content/FAQ/playground/guide; `playground-page.tsx` reuses the public endpoint. `widget/chatbox.js`: IIFE, scoped CSS under `#f1genz-chatbox-root`, FAB+panel, localStorage session id, fetch POST, link cards, vi-VN strings.

**Not built (per plan):** Phase 5 DeepSeek tool-calling (`search_products`, `check_inventory`, `lookup_order_verified`, `search_faq`, `create_lead` + staff tools), Phase 6 quick-replies/ScriptTag auto-inject, Phase 7 staff chat, Phase 8 pilot. NO real-time transport — no WS/SSE/polling; the "real-time contract" is strictly single-shot POST→JSON.

## Critical Edge Cases / Traps / Workarounds

1. **orgid-as-shopId tenant bug** — `knowledge.controller.ts` uses session `orgid` as `shopId` in 4 call sites; `FaqService`/`SyncService`/`ChatStatsController` all resolve `Shop.id` first. Effect: admin-created custom docs stored under a key no public query matches → silently dead content; `DELETE /api/app/knowledge/:id` can't remove sync-created docs. Not a cross-tenant leak (orgid unique) but broken feature + isolation-hygiene violation.
2. **Origin allowlist bypass** — `assertOrigin` rejects only when Origin present AND not allowlisted; curl/server-side callers send no Origin → unrestricted `/api/public/chat` + `/api/public/leads`. Mitigations: rate limit + installed-domain requirement. Allowlist gives false sense of restriction.
3. **Stuck states** — (a) `WebhookEvent` crash mid-reducer → `status='processing'` forever; `nextRetryAt` written but NO sweeper reads it (queue/worker is recipe-only). (b) `SyncService` status Redis-only (`sync:status:{orgid}`, TTL 3600s): crash/flush → `status:'running'` forever → `startBootstrap` early-returns; shop can't resync until TTL expiry.
4. **SameSite misclassification for VN domains** — `siteHost()` hardcodes 15 multi-part suffixes (co.uk, com.au…) but NOT `com.vn`/`net.vn`/`org.vn`. `app.shop.com.vn`+`api.shop.com.vn` → different siteHosts → `SameSite=None;Secure` (over-permissive) for same-site deploy.
5. **Silent in-memory Redis fallback** — `RedisService` without `REDIS_HOST` degrades to a `Map`: getDel/setNx/locks atomic only within one process — multi-instance deploy split-brains OAuth state, handoffs, locks, rate limits. `IngressRateLimitService` memory buckets unbounded (leak under fingerprint spray). env.schema requires REDIS_HOST in prod (good) but the silent fallback deserves a boot warning.
6. **INCR+EXPIRE race** — `redis.incr` sets `expire` only when value===1; crash between INCR and EXPIRE → permanent rate-limit key → perma-429 for that fingerprint. Fix: Lua INCR+EXPIRE atomically.
7. **Widget config ordering + domain hardcoding** — `F1GENZ_CHATBOX_CONFIG` must precede `chatbox.js`; `shopDomain` hand-typed per shop (404 'not installed' on typo); widget never auto-detects `location.hostname`. `productLinks` builds `https://{host}/products/{handle}` from the widget-supplied domain — myharavan config on a custom-domain shop yields wrong-host links.
8. **Public response leaks internals** — `/api/public/chat` returns raw `results` (chunk text + `sourceType`/`sourceKey` = internal product/FAQ ids) to anonymous callers; `ChatMessage.sessionId` stores unbounded client strings (no cap → DB bloat); ChatMessage write fire-and-forget → stats undercount.
9. **No timeouts on LLM/embedding/Haravan fetches** — all bare `fetch`: hung provider blocks the public request (rate bucket still burns). LLM failure does fall back to retrieval reply — but only after socket death.
10. **Catalog staleness** — sync is manual full-bootstrap only; no products/orders webhook topics subscribed (`WEBHOOK_SUBSCRIBE_TOPICS` = lifecycle only) → inventory/price answers stale until re-sync.
11. **HMAC launch edge (correct, keep as reference)** — `buildQueryMessageCandidates` verifies decoded AND raw-order serializations; `verify-hmac` falls back to OAuth only when `hmac` ABSENT — present-but-invalid fails closed; `code`+`hmac` together rejected client-side as ambiguous.
12. **Subscription-before-install** — `app_subscriptions/update` exempt from mapped-domain requirement; snapshot persisted under correlation keys (orgid/domain/subscriptionId/payloadHash), applied at install — correct pattern for Haravan ordering.
13. **Domain hijack guards** — install tombstones prior active owner in same tx as upsert; `shop/update` only saves mappings whose resolved orgid equals event identity; deterministic `ShopDomain.id='{orgid}:{domain}'` + partial unique `UNIQUE(domain) WHERE active`.

## Concrete Improvements for Super Core

- **Import the scanner as a rule pack.** `scripts/scan-anti-patterns.mjs` operationalizes 11 rules; `docs/anti-patterns.md` + `docs/source-extraction-map.md` give bad/required pairs with source-app file:line evidence. Direct `core.record_anti_pattern` candidates: `jwt.decode()` identity trust; non-atomic OAuth state consume (get→del vs GETDEL/Lua); static nonce; direct no-HMAC session from `shop+orgid`; session token in URL/localStorage; parsed-body webhook HMAC; header/query orgid trust; random webhook idempotency fallback; Redis KEYS in prod paths; non-owner lock release; hardcoded proxy BACKEND_URL fallback; `pm2 --watch`/`npm install` deploys.
- **New anti-patterns this repo adds:** (a) *orgid≠shopId* — auth-principal id vs tenant FK confusion; rule: 'never pass session identity as tenant FK; resolve Shop.id once per request'. (b) *Origin-header-optional allowlists* — 'an origin check that passes when Origin is absent is not an allowlist'. (c) *Redis-only job status* — 'status living only in cache can lie forever; persist run state or bound with heartbeat/dead-man TTL'. (d) *Hardcoded public-suffix lists* — 'cookie site detection needs real PSL or explicit config; regional ccTLDs (com.vn) break hand-rolled lists'. (e) *INCR-then-EXPIRE* non-atomic rate limiting. (f) *fetch without AbortSignal* on public endpoints.
- **Platform semantics (Haravan):** webhook headers `x-haravan-hmacsha256|x-haravan-hmac-sha256|x-haravan-hmac`; topic `x-haravan-topic|x-haravan-webhook-topic`; event id `x-haravan-webhook-id|x-haravan-id|x-request-id`; uninstall aliases (8 variants incl. `app_uninstall_webhook`); GET challenge = `hub.verify_token`+`hub.challenge` plaintext echo (separate secret from POST HMAC); launch HMAC = hex sha256 over raw query minus `hmac`, ±300s; install scope needs `grant_service wh_api`; commerce `apis.haravan.com/com/{products,orders,customers}.json?page&limit`; subscribe `POST webhook.haravan.com/api/subscribe` bearer; `orgsub` claim → `{orgsub}.myharavan.com`; subscription webhooks may precede install.
- **Fix patterns:** lifecycleGeneration conditional write for uninstall-vs-refresh (`updateMany where {orgid,generation,status}`, count≠1→discard); domain tombstone-prior-owner tx on reinstall; deterministic idempotency `sha256(topic:identity:payloadHash)` when provider event id absent; snapshot-correlation for pre-install webhooks; per-doc `ROW_NUMBER` partition for RAG top-k; content-hash short-circuit to skip re-embedding unchanged docs.
- **Workarounds:** `Unsupported("vector")` Prisma column → create row then `$executeRaw UPDATE ... CAST(? AS vector)`; ioredis<6.2 lacks `getdel` → Lua get+del fallback (in `redis.service.ts`); `ShopDomain` active-unique needs partial index via raw migration (Prisma can't express `WHERE active`).

## Concrete Improvements for Haravan Theme Core Output

- **Widget embed = first-class theme-injection contract** for ThemeCompiler: ordered pair `<script>window.F1GENZ_CHATBOX_CONFIG={apiBaseUrl,shopDomain}</script>` + `<script src=...>` before `</body>` (docs/storefront-embed.md). Ordering is load-bearing — config must exist before widget executes (mount is DOMContentLoaded-gated). A schema generator emitting an app-embed snippet should render `shopDomain` from `{{ shop.domain }}`/request host instead of merchant hand-typing — the manual step is the #1 install failure mode (404 'not installed').
- **DOM sanitizer allowlist:** widget injects `<style>` + fixed FAB `z-index:99999` under `#f1genz-chatbox-root` with `fcb-*` classes. A sanitizer stripping inline `<style>`, `position:fixed`, or unknown ids silently kills it; conversely widget CSS is root-scoped (no Shadow DOM) so theme CSS bleeds in — treat third-party widget roots as opaque islands.
- **noPS/pagespeed interaction:** script-deferral pipelines must preserve config-before-widget ordering and not rewrite the cross-origin `apiBaseUrl` fetch; defer injection is safe (DOMContentLoaded-gated), async reorder is not.
- **Settings contract:** widget needs exactly two merchant settings (apiBaseUrl, optional shopDomain override) — candidate `settings_schema` app-block; colors (`--c`) and strings are hardcoded vi-VN → i18n props the schema generator must expose for multi-language themes.

## Concrete Improvements for AntiFan Core & Site Clone

**AntiFan Core:**
- **Dynamic fixed overlay** — `visual.compare`/`screenshot.full_page` on storefronts with this widget need deterministic masking of `#f1genz-chatbox-root` (FAB always visible; panel state-dependent; 'Đang trả lời…' typing indicator timing-sensitive). `media.freeze` won't help — it's DOM, not animation; mask by selector.
- **Chat-widget verification claims need network proof, not DOM** — 'chatbot answers' is only verifiable by intercepting `POST /api/public/chat` response (CDP Fetch/Network); DOM-only assertions race the fetch. Record as claim-type: storefront-widget claims require request/response capture.
- **`inspect.page_inventory` trap:** fixed widgets never appear in scroll-flow inventory — separately enumerate `position:fixed` high-z roots or the report says 'clean' while an overlay covers content.
- **localStorage pollution:** `f1genz-chatbox-session` persists across clone/verify sessions — `reference.capture`/`export_clean` should snapshot+clear namespaced widget storage keys for deterministic diffs.
- **Sanitization parallel:** `theme.export_clean` strips unhydrated blobs; this widget is the opposite — a *runtime-injected* root a 'clean export' should preserve-or-strip by policy (third-party, not theme DOM).

**Site Clone:**
- **IR model:** represent the widget as an `external-service` component node with props `{apiBaseUrl, shopDomain, sessionStrategy:'localStorage'}` — not static markup. Cloned DOM captures at most the FAB (panel `display:none` until opened); the IR must record the script pair + config object as source of truth.
- **Offline standalone:** `/api/public/chat` unreachable offline → DoD validator should classify `degraded-external` (renders, sends, shows 'Kết nối lỗi' fallback) rather than pass/fail; optionally stub the endpoint with a canned reply for demo value.
- **Asset pipeline:** `chatbox.js` may be served from app CDN (not shop domain) — treat cross-origin script+config as one atomic asset unit; script without its preceding config block = dead widget (console.warn + early return).
- **Component contract IR:** public contract `{config globals, POST /api/public/chat {shopDomain,message,sessionId} → {reply,links[]}}` — clean example for an 'external API binding' field; `/api/public/leads` exists server-side but unwired in the widget (dead capability worth flagging in clone audits).
