## 2. Architecture & Role

Three-runtime app: (a) NestJS API on Express with `bodyParser:false` + manual `express.json` raw-body capture (main.ts:11-15, 60-64); (b) admin SPA served via Cloudflare Pages with a `/api/*` function proxy; (c) storefront web-component bundle served from `/storefront/*` and installed via `.bwt` snippets reading shop/product metafields.

Platform layer `src/sapo/*` is a faithful, hardened port of the haravan-app-base lifecycle contract: OAuthState (hashed key, GETDEL atomic consume, 30min TTL), HmacVerifier (sorted-A-Z launch query ±300s; raw-body webhook HMAC hex|base64), SessionService (HMAC-JWT + one-time handoff code + SameSite=None/Lax cookie), TokenEncryption (AES-256-GCM), ShopDomain (Redis+DB domain→storeDomain, tombstone-aware), LifecycleLock (owner-token compare/delete), WebhookService (HMAC→normalize→identity cross-check→idempotent insert→inline reducer), WebhookRegistration (degraded/failed status surfaced), Subscription (pre-install snapshot correlation), Uninstall (locked cleanup preserving merchant data).

Domain: review + qna (Postgres source of truth, per-product Redis write lock, `f1genz_reviews.public_summary` metafield sync), catalog (backfill + webhook upsert/soft-delete), purchase (verified-buyer hashes), media (HMAC ticket → R2 worker), dashboard/ops (health, resync, backfill).

## 3. Load-bearing Files & Contracts

- **Sapo OAuth**: `https://{store}.mysapo.net/admin/oauth/authorize` + `POST /admin/oauth/access_token` (sapo-api.service.ts:185-197); permanent token, no refresh; identity verified via `GET /admin/store.json` accepting `store ?? shop` wrapper (sapo-api.service.ts:200-207). NOTE: docs/sapo-auth-flow.md says `/admin/shop.json` — code uses `/store.json`; unverified which Sapo actually serves.
- **HMAC**: launch query sorted A-Z by decoded key, `key=value&…`, HMAC-SHA256 hex, timestamp ±300s mandatory (hmac-verifier.service.ts:60-85); webhook body HMAC accepts 64-hex or base64 (87-100). Distinct `SAPO_WEBHOOK_SECRET` enforced at startup (env.schema.ts secrets-distinct check).
- **Webhooks**: POST `/api/oauth/install/webhooks` only; GET returns 200 stub (no Sapo challenge). Idempotency key = `provider:{topic}:{identity}:{eventId}` or `sha256(topic:identity:payloadHash)`; unique-violation → inProgress/duplicate/retry-failed (webhook.service.ts:150-240). 11 subscribed topics incl. orders/* — but orders reducer is a stub returning `{queued:true}` (webhook.service.ts:215-218).
- **Metafields**: Sapo `value_type` limited to `string|integer`; JSON serialized to string (sapo.types.ts:95-130). Only `f1genz_reviews.public_summary` written per product (D4); `f1genz.config` shop metafield carries `{apiUrl, storeDomain}`.
- **Session**: handoff code `sapo_handoff_<64hex>` Redis GETDEL → HttpOnly cookie + **also `sessionToken` in JSON** (sapo.controller.ts:198-220) — the JSON token is what the SPA persists to localStorage.
- **Public API**: `/api/public/reviews|qna|media` keyed by `x-store-domain` header or `storeDomain` query, regex-validated but **never resolved through ShopDomainService** — the raw domain is used as AppInstall key.
- **DB**: prisma/schema.prisma — Shop/AppInstall (encrypted token cols, lifecycleGeneration, tokenVersion, webhookRegistrationStatus, featuresUnlocked)/ShopDomain (active-tombstone)/SubscriptionSnapshot/WebhookEvent (idempotencyKey unique)/CatalogProduct/CustomerPurchase/ReviewProduct/QnaQuestion.

## 4. Critical Edge Cases / Traps / Workarounds

**Breakage-class (verified in code):**
1. **Storefront widgets render empty.** `getPublicReviews`/`getPublicQuestions` do `Array.isArray(payload.data)` (f1genz-storefront.js:488-509) but both endpoints return `{items,total,page,pageSize}` (review.service.ts:560-590, qna.service.ts:375-400). Every review/Q&A list is `[]`.
2. **Custom-domain stores fail all public endpoints.** `.bwt` emits `storeDomain="{{ shop.domain }}"`; `extractStoreDomain` uses it verbatim as AppInstall key (public-review.controller.ts:70-80). Installs are keyed by `*.mysapo.net`; a shop whose `shop.domain` is a custom domain → 409 `App not installed`. ShopDomainService mapping exists but is never consulted on public routes.
3. **Admin review/QnA 404 in production.** Client calls `/admin/reviews` + `/admin/qna` (ApiService.js:56-176); `_routes.json` proxies only `/api/*` and `_redirects` sends `/admin/*` to index.html. Works in dev only because vite.config.js proxies `/admin`.
4. **PM2 worker is a duplicate API.** `PROCESS_ROLE` set in ecosystem.config.cjs but never read in src/ → second process binds same PORT → crash loop.
5. **Verified-purchase feature dead.** `orders/*` webhooks subscribed + persisted but reducer stubbed; `customer_purchases` never populated → `requirePurchaseToReview`/`purchase-eligibility` always `not_purchased`.
6. **verify-hmac endpoint broken twice.** Reads `params.get('storeDomain')` but Sapo sends `shop` (sapo.controller.ts:113-118) → 400; and returns `{handoffCode,...}` while client expects `{valid,orgid,sessionToken}` (login/index.jsx:154-167) → always falls back to OAuth, leaking orphan handoff codes.
7. **Anti-pattern scan is a silent no-op.** `scanRoots=['server/src',...]` (scan-anti-patterns.mjs:7) — no such dir; misses real violations: `localStorage.setItem('auth_session_token')` (AuthStorage.js), `BACKEND_URL || 'https://api-haravan-reviews.f1genz.dev'` hardcoded fallback ([[path]].js:11 — wrong platform host too), `sessionToken` in exchange JSON.
8. **Summary batch overflow.** Storefront batches up to 250 productIds (REVIEW_SUMMARY_BATCH_LIMIT, f1genz-storefront.js:207); server slices to 100 (review.service.ts getPublicSummaries) → badges 101-250 silently empty.
9. **`.bwt` metafield access inconsistent.** Snippet 1 reads `f1genzConfig.apiUrl` directly on the metafield string; snippet 4 uses `| json_parse`. If Sapo returns raw string, loader config is undefined → falls back to hardcoded legacy host.
10. **Hardcoded legacy API fallback.** `LEGACY_FALLBACK_API_URL='https://api-sapo-reviews.f1genz.dev'` (f1genz-storefront.js:4) — any store missing the config metafield phones home to a fixed host; also a clone/DoD hazard.
11. **Dead/brittle paths:** `verifyChallenge` (Haravan GET challenge) dead code; `runBackground` no-op + bg limiter unused; ScriptTag API implemented but never called (no auto theme install); `/install/grandservice` SPA route + `authService.install` target a server route that doesn't exist; `installCallbackGet` redirects to `buildLoginUrl({storeDomain: store})` from an unsigned query param; failed webhook events get `nextRetryAt` but no retry worker exists; `listAllReviews`/`getAllQuestions` load entire shop tables for status counts; `getPublicReviews` sort ternary is dead (`'createdAt':'createdAt'`).
12. **Doc drift:** `docs/env-contract.md`, `architecture-contracts.md`, `oauth-install-login.md`, `security-checklist.md`, `getting-started.md`, `deploy.md` are haravan-app-base docs (HRV_*, OIDC/JWKS, `/install/grandservice`) shipped inside the Sapo repo; dev-guide page shows Liquid `{% %}` + `orgid=` snippets for a `.bwt` platform.

**Strong patterns worth extracting:** deterministic webhook idempotency with inProgress/duplicate/failed-rerun tri-state; stale-install-callback rejection (`oauthState.createdAt < uninstalledAt`); domain tombstone + active-unique reinstall model; per-store fg/bg limiter with shared cooldown on 429; subscription snapshot correlation keys for pre-install arrival; secrets-distinct + placeholder + HTTPS-origin production env validation; PII scrub on public mappers; upload ticket bound to store+product+file metadata.

## 5. Improvements for Super Core (@antifan/super-core)

**Platform semantics (sapo):** sorted-A-Z launch HMAC (vs Haravan raw-order); `X-Sapo-Access-Token` header; per-store `{store}.mysapo.net/admin` host (no central API); permanent tokens (no refresh — keep tokenVersion/lifecycleGeneration only for uninstall races); metafield `value_type` ∈ {string,integer} → JSON-as-string; `.bwt` exposes `shop.metafields`/`product.metafields` (D2 CONFIRMED); no GET webhook challenge; webhook topic alias families (app_uninstall_webhook, app_charge_update, orders/canceled|cancelled); `store.json` response may wrap as `store` or `shop`; shop.domain may be custom domain ≠ install domain → always map via domain table.

**Anti-patterns to record:** (1) porting a scan/verify script without updating its roots → silent green; (2) env-driven process role with no runtime branch → duplicate listener; (3) mixed `/api/*` and bare `/admin/*` route prefixes under a path-scoped edge proxy; (4) session token in exchange JSON → client persists to web storage, defeating HttpOnly contract; (5) public endpoints trusting caller-supplied tenant domain without domain→install resolution; (6) subscribing webhook topics with no consumer → dead data + false readiness; (7) hardcoded production fallback host inside a distributable runtime; (8) `process.env` read inside a service bypassing injected config (webhook-registration.service.ts:35); (9) client batch limit > server cap → silent truncation; (10) metafield JSON access without `json_parse` in .bwt.

**Fix patterns:** webhook tri-state idempotent insert; lifecycle lock + generation guard on install/uninstall; stale-callback timestamp check; domain tombstone + partial-unique active index; correlation-key snapshot store; per-store dual-bucket limiter with Retry-After cooldown; HMAC ticket-bound uploads; PII-scrubbing public mappers; fail-closed env schema with distinct-secret check.

**Workarounds:** 409/422 on webhook create = already-exists; metafield read→update-or-create for config; `/account` HTML scrape for Sapo customer identity (fragile — needs a verification claim + fallback); in-memory Redis fallback for dev (must be production-gated — currently isConfigured=false silently downgrades locks/rate limits to per-process).

## 6. Improvements for Haravan Theme Core Output

- **ThemeCompiler needs a platform-dialect emitter.** This repo proves one widget contract must emit two dialects: Liquid `{% assign/if %}` + `.value` metafield access vs `.bwt` `{{ assign/if }}` + `json_parse` filter. The hand-written `.bwt` already drifted (snippet 1 missing `json_parse`, stale Liquid in the admin dev guide). Generate both from one IR so metafield-access semantics can't diverge.
- **Canonical element-attribute contract.** `orgid` (Haravan) vs `storeDomain` (Sapo) drifted inside one repo: runtime reads `storeDomain`, dev guide emits `orgid`, server redirects set `orgid=<storeDomain>`. The compiler should own one attribute name map per platform and validate emitted snippets against the runtime's `observedAttributes`.
- **Settings contract single-source.** Storefront `DEFAULT_CONFIG` has ~40 keys; server `WidgetConfig` persists only `formPhoneMode`+`reviewQnaDisplayMode` (widget-config.interface.ts) — admin saves are silently dropped for the rest. Schema generator should derive server DTO + admin form + storefront defaults from one definition.
- **DOM sanitizer / escaping rules:** `distribution='{{ publicSummary }}'` injects raw JSON into an attribute; `{{ product.title | escape }}` in JSON-LD; runtime escapeHTML on all review content — encode these as required sanitizer rules for generated snippets.
- **Public-API shape contract.** The array-vs-page-object break is exactly the class of drift a generated `data-contract` (endpoint → response shape → consumer expectation) would catch at compile time.

## 7. Improvements for AntiFan Core & Site Clone

**AntiFan Core:**
- Verification claims this repo illustrates: `PUBLIC_API_SHAPE` (page object vs array — would have caught bug #1), `CUSTOM_DOMAIN_IDENTITY` (storeDomain resolution — UNVERIFIED/broken), `EDGE_PROXY_COVERAGE` (`/admin/*` outside `_routes.json` — broken in prod), `PROCESS_ROLE_SWITCH` (declared, never implemented), `SCAN_COVERAGE` (scanner roots exist — false green), `METAFIELD_DIALECT` (json_parse requirement — inconsistent). These are reusable claim types for storefront-app verification.
- CDP/telemetry: public CORS echoes any Origin on `/api/public`+`/storefront` (by design) — telemetry should record reflector scope; webhook route intentionally has no IP rate limit (shared Sapo source IP) — record as platform semantic, not a finding.
- SnapDOM/sanitization: the runtime scrapes `/account` HTML and regex-extracts email/phone (f1genz-storefront.js:96-155) — sanitizers must treat account-page captures as PII-bearing and the regexes as false-positive prone.
- `theme_debug_bundle`/`qa_validate` surfaces map directly onto this app's dual-mode storefront (metafield SSR + API fallback); the storeDomain-resolution bug is detectable live via widget placeholder state.

**Site Clone (@antifan/site-clone):**
- Component contract IR should capture: 5 custom elements (`f1genz-reviews`, `f1genz-reviews-panel`, `f1genz-qna-panel`, `f1genz-rating-badge`, `f1genz-product-schema`), attribute map (product-id, storeDomain, customer-email/phone, avg-rating, review-count, distribution), runtime config resolution chain (window.__F1GENZ_STOREFRONT_CONFIG → script data-api-url/src origin → legacy fallback), metafield schema (`f1genz.config`{apiUrl,storeDomain}, `reviews.public_summary`{avg,count,distribution}), and the `/api/public/*` endpoint map keyed by storeDomain.
- Asset pipeline: runtime JS/CSS served from API origin with mtime re-read + `max-age=300,swr=86400`; a clone must localize or preserve the loader contract; review media points at external R2 CDN (`images-sapo.f1genz.dev`) — asset manifest must include it.
- Offline standalone mode: widget is API-dependent — offline mode needs fixture capture of `/api/public/reviews|qna|media` per storeDomain+productId, plus a stubbed `__F1GENZ_STOREFRONT_CONFIG`.
- DoD validator additions: (a) flag residual external API hosts in cloned runtime (the LEGACY_FALLBACK pattern = silent phone-home); (b) require config metafield or injected window config; (c) assert custom elements defined ∧ attributes resolvable; (d) assert tenant domain resolves through domain map, not raw `shop.domain`; (e) dialect parity check Liquid↔.bwt; (f) JSON-LD emitted only when count>0; (g) no PII scraped from account pages in offline artifacts.
