# Ultra Scout Report: F1GENZ Feedback (E:\Work\apps\F1GENZ Feedback)

## Project & Directory
Internal feedback/issue tracker for the F1GENZ theme team (Haravan/Sapo storefront work). Layout: `server/` (Express backend, own git repo via `.git-nested`), `client/` (Cloudflare Worker + SPA, own `.git-nested`), `docs/` (journals + superpowers specs), `.playwright-mcp/` (a11y-tree evidence snapshots).

## Architecture & Role
Three runtime components:
1. **server/** — Express monolith (`server.js`, 2072 lines) on a VPS under pm2 (`feedback`), deployed by GitHub Actions SSH (`git reset --hard` + `npm ci` + `pm2 reload`). Optional Dockerfile (node:18-alpine). Google Sheets is the only database.
2. **client/** — Cloudflare Worker serving `public/index.html` (2777-line vanilla SPA) and proxying `/api/*` to `api-feedback.f1genz.dev/api/exec` with `x-api-key` injected from a worker secret. Also handles `/api/upload-image` (direct R2 put) and `/api/my-ip` (dev-feature IP gate).
3. **Data plane** — Sheet `Feedback` columns A–Q (ID, Deadline, Host, Shop, Link, Stage, Tags, Dev_note, Image_note, Note, Time, Message, MessageID/creatorId, ImageID, UpdatedAt, Priority, DoneAt); sheet `Intruction` [sic] for guides; `History` (logging disabled). Images: Telegram file_id → getFile → download → R2 `telegram/` → CDN URL cached in `imageUrlCache` and written to col N; fallback `/api/telegram-image?raw=1` proxy so bot token never reaches clients.

**Identity model**: rowNumber is the public key everywhere (Telegram `#N` refs, `?feedback=N` share links, API params) while col A holds a `Date.now()` id used only to re-locate rows after writes.

## Critical Edge Cases / Traps / Workarounds
1. **Committed secrets**: `.env.example` holds the real API_KEY, TELEGRAM_BOT_TOKEN, R2 access/secret keys, SHEET_ID, account ID — live-looking values in git.
2. **Unauthenticated surfaces**: Telegram webhook has no `secret_token` verification (forged updates → create/delete feedback, spam group); `/api/telegram-setup` + `/api/telegram-info` bypass the API key via the `/telegram-` prefix skip → anyone can re-point the bot webhook; worker `/api/upload-image` has zero auth → public R2 write.
3. **Row-number identity fragility**: `del` reply and `deleteFeedback` physically delete rows → all higher rowNumbers shift; `?feedback=N` share links, Telegram `#N` refs, in-flight UI state silently retarget. `repairFeedbackSheet` exists because shifted/orphan rows actually happened.
4. **Append race**: `getNextFeedbackRowNumber` scan-then-`values.update` loses concurrent appends (last writer wins); `isCanonicalFeedbackRow` (12–16-digit ID or host/shop/stage non-empty) can classify real rows as non-canonical → next append overwrites them.
5. **Formula injection**: every write uses `USER_ENTERED`; text starting `=`, `+`, `-`, `@` becomes a live formula in the sheet.
6. **R2 circuit breaker never resets**: `handleR2UploadError` sets `r2AuthDisabled=true` permanently (until restart) — `r2UploadDisabledUntil` backoff is dead code; one transient 403 disables all image mirroring and `uploadTelegramPhotoToR2` returns `'Error: ...'` strings that flow into comment text.
7. **Creator mapping contradiction**: ID `801593125` → 'Nghĩa' in `TELEGRAM_ID_TO_HOST` (comment admits unresolved conflict with 'Tuan') but → 'Tuấn' in `resolveFeedbackCreator`. Same ID, two names, two subsystems.
8. **JSON-in-cell comments**: col H stores a JSON array; unparseable content → silently replaced by `[]` (data loss) or wrapped as 'Note cũ'; marker protocol `[IMAGE]url`/`[TG_IMAGE]fileId` duplicated server (`extractCommentImageUrls`) and client (`parseCommentImages`) — drift risk.
9. **Stored XSS sinks**: `renderTable` injects `r.shop`, `r.host`, `r.stage`, `r.note`, `r.creatorName` unescaped into innerHTML; `r.link` interpolated raw into `window.open('...')` onclick (quote breakout → JS execution); `renderComments` emits `c.author` unescaped. `escapeHtml` exists but applied inconsistently.
10. **GET with side effects**: `getDashboardData` triggers `cleanupOldDoneFeedbacks` (deletes rows); `cleanupArchivedFeedbacks` is a destructive GET — both reachable via GET `/api/exec`.
11. **Dev gate by obscurity**: `checkDevPermissions` enables 'Copy for AI' via hardcoded IP `118.68.211.157` (worker + api.ipify fallback) or `?dev=1` persisted in localStorage — anyone can self-enable.
12. **Doc drift**: README claims reply `del` sets Stage=Deleted; code deletes the row. Stage 'Deleted' still appears in the stage filter (legacy data).
13. **Telegram file_id ephemerality**: file_ids expire → R2 mirror mandatory; `sendTelegramPhoto` fast-path sends raw file_id (may 404 later); `[TG_IMAGE]` markers depend on the proxy endpoint forever.
14. **Multi-host parse**: two host names in one message → `host='A;B'` breaks exact-match host filters/counts.
15. **`//` overload**: list command vs reply-transfer prefix — same token, context-dependent meaning.
16. **Priority rewrite**: `updateFeedbackPriority` batch-writes col P for EVERY row on each drag save — O(N) Sheets calls; 5s auto-refresh × N users vs 10s cache TTL → quota pressure (mitigated by stale-serve 5min on Sheets 503, but cold-start outage = dead dashboard).
17. **Timezone fragility**: `formatVNTimestamp` builds a Date from `toLocaleString('en-US',{timeZone})` then re-reads parts — ICU/locale dependent; `parseVNTimestamp` regex must handle both `HH:mm:ss dd/MM/yyyy` and `dd/MM/yyyy HH:mm:ss` orders seen in data.
18. **Unbounded state**: `imageUrlCache` Map never evicts; `telegramMediaGroups` entries die with the process (album lost on restart mid-debounce).
19. **Workarounds worth keeping**: `dns.setDefaultResultOrder('ipv4first')` + `family:4` in `telegramRequest` (VPS IPv6→Telegram ETIMEDOUT); optional-require `compression`; stale-cache-on-Sheets-outage; descending-sort before `deleteDimension` (correct delete pattern); NFD diacritic strip + `đ→d` in `normalizeText` (Vietnamese-insensitive matching); sequential sends to avoid Telegram ETIMEDOUT.
20. **Metadata falsehood**: `.workspace-context.json` declares `nestjs-api`/`react-spa` — actual stack is Express/vanilla. Any tooling trusting that file is misled.

## Improvements for Super Core
**Anti-patterns to record:** (a) spreadsheet-as-DB with positional row identity — symptoms: shifted refs, rescue routines, broken share links; replacement: stable UUID primary key + append-only log or real DB; (b) JSON-blob-in-cell for collections — silent-loss parse fallback; (c) secrets in `.env.example` — the file that is *supposed* to be safe; (d) webhook without secret_token + auth-skip by path prefix (`/telegram-` also exempted setup/info endpoints); (e) GET endpoints with destructive side effects; (f) circuit breaker that latches permanently while advertising a timed backoff; (g) client-side feature gates keyed on IP/localStorage; (h) marker-string protocols (`[IMAGE]`) duplicated across server/client without a shared codec.
**Fix patterns to record:** descending-sort-then-deleteDimension for row deletes; single pure helper (`resolveDoneAt`) as stage-transition authority instead of scattered logic; debounced media-group aggregation keyed `chatId:media_group_id`; stale-while-error cache (10s TTL, 5min stale) for Sheets outage survival; background mirror with proxy fallback for ephemeral media.
**Platform semantics:** Telegram file_id is ephemeral → mirror to permanent storage; bot token lives in API URLs → never expose direct file URLs to clients (proxy); albums arrive as N separate updates sharing `media_group_id`; Google Sheets `USER_ENTERED` evaluates formulas → sanitize `=+-@` or use RAW; `values.append`+`insertDataOption` beats manual row computation; R2 S3 endpoint uses `region:'auto'` and `{accountId}.r2.cloudflarestorage.com`; Workers `[assets]` + `env.ASSETS.fetch` for static SPAs; `wrangler secret put` for keys.
**Workarounds:** force IPv4 (`family:4`, `dns.setDefaultResultOrder`) for Telegram from VPSes with broken IPv6; optional-require for compression.
**Practice parity:** `.workspace-context.json` declared stack ≠ observed stack — add a parity rule: workspace context files must be validated against package.json/imports before use.

## Improvements for Haravan Theme Core Output
- **Issue-intake contract**: this app is the upstream bug-report system for Haravan theme work. Its row IR (shop domain, doc link, note, image URLs, platform tags `haravan|sapo|hrv|gap|baogia`) plus `copyAIPrompt`'s markdown spec (storefront URL, evidence images, AI-readable Docs/Sheets export links, explicit fix-request section) is a proven shape ThemeCompiler/HaravanSchemaGenerator could consume directly as a 'theme issue' input contract — including the `docs.google.com/.../export?format=txt|csv` trick for machine-readable attachments.
- **Sanitizer lessons**: the XSS sinks here (unescaped sheet data into innerHTML, raw URL into inline `window.open`) are exactly what the DOM sanitizer must catch when merchant/user content is injected into theme settings or section markup — enforce escape-by-default and never interpolate URLs into inline handlers.
- **Schema single-source**: the A–Q column map is duplicated in three places (`getAllData`, `rowArrayToFeedback`, `createFeedback` literal) — already drifted once (col M = MessageID AND creatorId). HaravanSchemaGenerator should emit one machine-readable mapping consumed by all readers/writers, and the settings contract should version the layout.
- **Formula-injection**: any theme pipeline writing merchant text to Sheets/CSV must sanitize spreadsheet metacharacters.

## Improvements for AntiFan Core & Site Clone
**AntiFan Core:** (a) verification claims — `.workspace-context.json` says `verified` while the DoneAt journal says 'live validation pending': bind claims to fresh evidence, exactly the `verification_record_claim`/`verify_claim` model; (b) DOM sanitization — treat all spreadsheet/webhook-originated text as hostile (this dashboard is a live XSS exhibit); (c) visual compare — the SPA auto-refreshes every 5s and renders timestamps/counts: `media.freeze`/dynamic-masking is mandatory for deterministic diffs on such polling UIs; (d) audits should detect client-side feature gates (`?dev=1`, IP allowlists) and unauthenticated upload endpoints; (e) `.playwright-mcp` a11y snapshots here match AntiFan's snapshot-evidence approach — keep correlating them with `inspect_snapshot` refs.
**Site Clone:** (a) asset pipeline — the file_id→R2→CDN + proxy-fallback + `imageUrlCache` dedup is the same ephemeral-URL→permanent-asset problem Site Clone solves; adopt permanent-copy-first with a bounded dedup map and a *recovering* breaker (this app's never-reset latch is the counter-example); (b) IR model — separate stable identity (col A id) from positional refs (rowNumber): component contract IR should never use DOM position as identity, and should version the schema (A–Q grew silently to include DoneAt); (c) offline standalone — `[TG_IMAGE]`/`[IMAGE]` markers and `/api/telegram-image` proxy URLs must be resolved to local assets or the DoD validator should fail the export (a 'standalone' clone that still calls the origin proxy is not standalone); (d) `.git-nested` renamed-repo convention — workspace/project-boundary detection must handle nested repos whose `.git` was renamed.
