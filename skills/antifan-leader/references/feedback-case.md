# Case: process F1GENZ feedback of Tài ("xử lý feedback", "xử lý feedback Taiz")

Read this file in full before touching a feedback job. Job bookkeeping (init, dispatch, wait, validate, verify, approve, close) is in SKILL.md "Job ledger"; discipline is in `leader-discipline.md`.

## Steps
1. Open the dashboard in an AntiFan tab: `anti.browser.tabs.create {url:"https://feedback.f1genz.dev/?host=Taiz&sort=time_asc", activate:false}`, then `anti.browser.wait {type:"dom-stable"}`. If it lands on Cloudflare Access login, stop and tell the user to sign in once in that tab.
2. Rows (wait for data, then filter by host in code). Keep the stable `id`: row numbers shift.
   `(async()=>{for(let i=0;i<40&&!(typeof originalFeedback!=='undefined'&&originalFeedback.length);i++)await new Promise(r=>setTimeout(r,300));return originalFeedback.filter(r=>r.host==='Taiz'&&/^(Feedback|Pending)$/.test((r.stage||'').trim())).map(r=>({id:r.id,row:r.rowNumber,shop:r.shop,link:r.link,note:r.note,stage:r.stage,deadline:r.deadline,tags:r.tags}))})()`
   - Stages on this dashboard: `Feedback` (new, open), `Pending` (waiting), `Done`, `Đã báo khách` (closed and reported to the client), `Deleted`. Only `Feedback` and `Pending` are work. Snapshot 29/10/2026: Taiz had 82 rows, 78 `Đã báo khách`, 2 `Done`, 1 `Deleted`, 1 `Feedback` (#294).
   - Before any read-to-act on a row, resolve the issue by its stable `id` (row numbers shift, see leader-discipline §5.3) and re-assert it is Taiz: `const x=originalFeedback.find(r=>String(r.id)===ID); x?.host==='Taiz'`, then use `x.rowNumber` from that same loaded list. If not, do NOT act. (The Leader itself never calls `quickUpdate`; the same guard is in every worker prompt.)
3. **Duplicate check before dispatch:** `terminal.list {includeBuffer:false}`; if any terminal whose `cwd` is that shop's folder has `run.state` `running`/`waiting_user`, or its `run.promptHead` mentions `#<row>`, or the folder holds `.tmp-copy<row>*` / scratch files for that row, someone is already on it: do not spawn; list it as "đang có terminal <id> làm" and ask the user.
4. Task text per row (no clipboard): `(async()=>{let c=null;const o=navigator.clipboard.writeText.bind(navigator.clipboard);navigator.clipboard.writeText=async t=>{c=t};try{await copyAIPrompt(ROW)}finally{navigator.clipboard.writeText=o}return c})()`.
5. Map shop → project folder. Folder names do not match shop domains reliably, and projects live outside `customizes/` too (`devs2\…`, `devs2\Haravan\…`, `devs2\Sapo\…`):
   - Search `E:/Work/.antifan-data/config/workspace-capsules.json` (`name`, `workspacePath`) for the shop name, matching case- and diacritic-insensitively (`hoangyengroup-1` ↔ "Hoàng Yến Group").
   - Search the binding files recursively, not only at the project root: glob `E:/Work/{customizes,devs2}/**/.haravan-cli_local.json` and `**/.hrv-sync-state.json` (skip `node_modules`, `.tmp-*`), and match the `org_id`/`theme_id` from the issue or the subdomain. A project with no binding at its root may still have one in a theme subfolder.
   - Accept exactly one bound folder; zero or several makes the row uncertain.
   - `shop` can be `admin.shopify.com` (a Shopify admin URL, not a store domain) while `tags` says `haravan` (seen on #294). That is a conflict: the worker header below is Haravan/hrv-only. Do not guess the store: ask the user which project folder and platform.
   - A request to copy/duplicate a theme first ("copy theme hiện tại rồi sửa trên theme copy", as on #294) is a remote theme operation (Haravan or Shopify duplicate/push). It always needs the user's explicit approval and is never a worker auto-step: ask the user, and only after approval let one worker create the copy, then bind work to the copy's theme id.
   - A Haravan project also needs a live `hrv` grant for its org (`hrv whoiam` lists orgs; many grants were expired/`invalid_grant` on 29/10/2026). If the worker reports it must run `hrv login`, that is NEEDS_INPUT for the user, never retry blindly.
   - Uncertain row: the Leader does not comment or change Stage itself. Tell the user why; if the user agrees, run one short worker round (cwd `E:/Work/scratch/leader`) whose only task is: comment on the issue why (skill `f1genz-feedback-comment-post`) and `quickUpdate(<row>,'Pending')` after the id/host guard, then report `STATUS: PENDING`.
6. Worker prompt file = the header (`LJ init` writes it from `scripts/leader/templates/worker-header.md` with the placeholders filled) + the copyAIPrompt markdown placed in `{{TASK}}`. Spawn one worker per row (respect concurrency), `name:"#<row> <shop subdomain>"`.
7. On each report (round 1):
   - DONE = the work is edited, verified by the worker and the issue comment is posted, but Stage is NOT Done yet. Run Leader verification (SKILL.md "Job ledger" steps), report to the user, and only after the user's approval send the idle worker the close follow-up below; that follow-up round is the only place Done is set.
   - PENDING is final (the worker already commented and set Stage Pending); verify it the same way.
   - NEEDS_INPUT → ask the user, relay, wait again.
   - FAILED → read the worker's last output, decide retry once or Pending.
8. Final message: table of rows with the Stage actually read back from the dashboard by `id`, and anything still waiting for the user.

When the user answers a LIVE-theme question with "được sửa", relay: `User duyệt sửa theme live <bound_id> cho issue #<row>. Làm tiếp từ bước 2.\r`. (The edit-guard still refuses a push to a live theme in the worker; see leader-discipline §5.5.)

## Close follow-up (only after Leader verification PASS and the user's approval)
`LJ approve`, then `LJ dispatch --job DIR --worker T --kind close` with no `--prompt`: the CLI generates the close prompt from `scripts/leader/templates/close-followup.md` ("User đã duyệt đóng issue <id>"). The idle worker must (1) re-check the guard by id (host Taiz, shop, sheet id), (2) `quickUpdate(<rowNumber by id>,'Done')` and confirm Stage by id, (3) write the new report round in `leader-report/1` format with `dashboard.stageAfter='Done'`, and do nothing else (no theme edit, no push, no further sheet cells). Pass the printed `input` unchanged to `terminal.write`. Afterwards run `validate-report`, re-read the Stage by id yourself and `LJ record --kind dashboard`.
