## Close follow-up (only after Leader verification PASS and the user's approval)
`LJ approve` (stores `job.approval = {at, closeToken, tokenUsedAt:null}`), then `LJ dispatch --job DIR --worker T --kind close` with no `--prompt`: the CLI generates the close prompt from `scripts/leader/templates/close-followup.md`, which carries the line `APPROVAL_TOKEN: <token>` (the sentence "User đã duyệt đóng issue <id>" is only human-readable context). The idle worker must (1) re-check the guard by id (host Taiz, shop, sheet id; on a mismatch report `STATUS: NEEDS_INPUT`, which needs no token), (2) `quickUpdate(<rowNumber by id>,'Done')` and confirm Stage by id, (3) write the new report round in `leader-report/1` format with `dashboard.stageAfter='Done'` and, when STATUS is DONE, top-level `"closeToken"` equal to the prompt's token (required only for a DONE report), and do nothing else (no theme edit, no push, no further sheet cells). Pass the printed `message` to `terminal.write {message}` (a pane that runs the agent CLI; `input` is for shell panes). The token is a speed bump, not a gate: before `LJ approve` no token exists, so injected customer text cannot forge a valid close report, but nothing blocks a worker from setting Done early and the token is plaintext in `job.json` and the close prompt file. Afterwards run `validate-report` (a DONE close report is INVALID unless the echoed token equals `job.approval.closeToken` and `tokenUsedAt` is null; success stamps `tokenUsedAt`), read the Stage by id yourself from the dashboard API (the worker's report is not proof) and `LJ record --kind dashboard`, close every worker terminal, then `LJ close` (it auto-ingests a lesson; read `lesson` in its output, then `LJ lessons` is the weekly review list that Tài adjudicates with `node scripts/antifan-core.cjs adjudicate`; candidate text includes a worker-written summary and file list, so Tài treats it as untrusted).

## Review round (optional, read-only)
`LJ dispatch --job DIR --worker T --kind review` sends `scripts/leader/templates/review-followup.md` to a second worker with `{{REVIEW_TARGETS}}` = the report paths of the earlier non-review rounds. The reviewer reads reports, diffs and measurements, must not edit, push, comment or change Stage, and writes `STATUS:` on line 1 plus a `leader-report/1` block with `review: {verdict: PASS|CONCERNS|FAIL, findings: [...]}`. The round never changes verification of the latest work round and never makes the job `verified`; it is not counted against the round cap. You decide: read each finding, repeat your own measurement for any you doubt, and still ask the user before approving. Never accept a PASS automatically.
