Loaded before the first `terminal.*` call of a task and whenever a pane misbehaves. `LJ` = `node E:/Work/apps/AntiFan/scripts/leader/leader-job.mjs`; `<leader-scratch>` = the job scratch root `LJ init` creates job folders in.

| Answer a worker's `ask` dialog (state `waiting_user`) | `worker-status.mjs --terminal T` / `wait-workers.mjs` / `LJ wait` (event `needs-input`) print `ask`: `questions[]` with `question`, `options[]`, `recommended`, `multi` and, per single-choice question, `answerKeys[optionIndex]` (e.g. `["down","enter"]`: the dialog opens on the recommended row, Enter selects). Pick the option (the user's answer, or your own decision under "Be decisive"), then `terminal.write {sessionId:T, keys: <answerKeys[i]>}` (answers one question; one question submits by itself). Several questions: send each question's keys in order (one call per question, or all in one `keys` list of at most 16), then the `finishKeys` of `ask` (`["enter"]`, the Submit tab): Enter on the last question only moves to the Submit tab, so without it the dialog stays open. The dialog is closed when `worker-status` shows `state` left `waiting_user` (`running` again, or `idle` if the turn ended) and no `ask`; `runSeq` does NOT grow, because answering resumes the same run. An answer that left it open (`ask` still printed) means the keys missed: read the terminal buffer, do not repeat blindly. To dismiss a dialog without answering: `terminal.write {key:"esc"}` (the worker gets a cancelled ask); Esc goes in its own call or as the last key of `keys`, because an Esc followed by another key in the same write reads as Alt+key. A `multi` question has no `answerKeys`: `esc` it and send a follow-up line. Plain Enter, Esc, Ctrl-C and the arrows exist only as `key` / `keys`: whitespace-only `input` is refused as "no usable value". Esc or an arrow sent to a terminal with a live OMP no longer makes the next plain line unreadable (04/11/2026: after an Esc the gate refused plain text until a Ctrl-C) |

## Worker lifecycle
- `terminal.create` with absolute `cwd` + `name`; start OMP by sending the `input` that `LJ dispatch` printed (`omp "@<abs path>"\r`); verify with `worker-status.mjs` (`runSeq:1`, `promptHead` matches the prompt, `ompAlive:true`). `terminal.write` `written:true` proves nothing; only `runSeq`/`promptHead` confirm that the prompt was taken.
- Close via `terminal.close` before `LJ close` (the ledger refuses while a worker terminal is open).
- `Ctrl-C` does NOT interrupt a running OMP; only `terminal.close` stops one reliably (`key:"ctrl-c"` is only for clearing an unsent shell line, see the 09/11 rules above).
- `worker-status.mjs` exits 4 `NO_RUN_FILE` for a closed terminal (no run file).
- Worker transcripts: `~/.omp/agent/sessions/*.jsonl`; `lastTool`/tool intents are in `worker-status` output, so do not open the JSONL by hand.
- Prompts need an explicit report path so a waiter can find the report: a prompt written by `LJ init`/`dispatch` carries `{{REPORT_PATH}}`; a hand-written prompt needs a `Report vào: <abs path>` line (the `wait-workers.mjs --mine` fleet watcher, see leader-discipline §5.18, reads that line or a `STATUS` line naming `<key>.report.md`), and `wait-workers.mjs --w` takes the path as the optional 4th field.
- Per-job rules: never hold a finished job back for a slower one (after each handled job run `LJ status --all`, then `wait-any` again if any job is still dispatched); ask per issue, and approve and close only the issues the user answered Done; a job the ledger does not know (no `LJ init`) is invisible to `wait-any`.

## Waiting facts
- `wait-workers.mjs --ignore` does not exist (exit 2, `unknown argument`). To stop a settled worker from waking the waiter again, drop `--mine` and pin the rest: `--w <terminal>,<writtenAt>,<minRunSeq> [--w ...] --all` (`--all` returns only when every pinned worker settled).
- A waiter wakes on events; its own exit is injected as a follow-up message. Do not loop `wait` and do not poll the waiter service. Read `proc://<waiter-id>` on a wake: `{"type":"event"}` lines plus one `{"type":"worker"}` line per worker; only DONE reports are finished work, idle lines of already-settled workers are noise.
- Event dedup keys: `report:<terminal>:<firstLine>`, `idle:<terminal>:<runSeq>`, `new:<terminal>@<incarnation>`. Give every waiter service a unique name.
- `terminal.wait` is capped at 28000 ms per call; `WAIT_TIMEOUT` at exactly that value is the cap, not a hang. Re-issue with `afterSeq`. After submitting, pass `afterEventAt:<writtenAt>` (run-idle never satisfies before an OMP run exists). To peek at progress use an output-match wait (`pattern:"STATUS: |not recognized"`, `timeoutMs:15000`); the `π ... <task>` footer plus the worker TODO list proves the prompt was taken.

## Staging a follow-up while the worker runs
`terminal.write` into a running OMP is `TERMINAL_BUSY` (`force:true` would inject text into the live prompt: avoid). Write the follow-up into its own file in the job folder (new scope, evidence required, corrected numbers), wait for idle, send one short `message` pointing at the file. Keep the same pane so the worker keeps its context. `LJ dispatch --kind followup` does exactly this and prints the `message` to send; copy it, never retype the path.

## User screenshots for a worker
Leader-side vision may be unavailable (`read` of a pasted image returns a placeholder; image judging of a session-store path is refused by `REFUSED_LEADER_INVESTIGATE`). Copy the pasted image from the OMP session store into the job folder (find it with `glob` over `~/.omp/**/pasted-image-<hash>.png`), and make "open it and transcribe what it shows (page, tab, empty field, wrong editor)" a numbered first step of the worker prompt; the worker puts the transcription into its evidence.

## Tool-call substitution (xd:// route)
Symptom: a request for `mcp__antifan_browser_terminal_create` / `terminal_write` executes a different tool, repeatedly. Do not retry; use the file-device form: `write {path:"xd://mcp__antifan_browser_terminal_create", content:'{"cwd":"<abs>","name":"<short>"}'}` and the same for `terminal_write`. Confirm with `worker-status.mjs --terminal <id>`: `runSeq:1` and a `promptHead` equal to your prompt file. A `promptHead` you never wrote means the pane took another first message: read the report before trusting the round.

## Leader bash after the investigate budget
The guard refuses a whole compound line containing `git branch` / `git status` (`REFUSED_LEADER_INVESTIGATE`). Get branch/sha/state from the worker report or a follow-up; an exact single-file `read` of a job file is still allowed.

## Gate and merge order (deploy jobs)
Worker round on a branch, then an independent gate worker (switch branch, typecheck + tests + client + scan, keep exit codes with `set -o pipefail`), then `merge --no-ff` into main, rebuild, push, deploy. Deploy, rollback and post-deploy watch rules: `git-and-cloudflare-safety.md`.

## Verify the deliverable (checklist before `LJ record`)
- The worker keeps a progress file and appends after every todo; a long run may compact mid-edit and the terminal buffer is not durable state.
- Read the artifact the worker names; spot-check 2-3 of its file claims with `grep`.
- No git repo at the project root: prove scope by walking mtimes (skip `node_modules`, `.git`, `.wrangler`).
- A repo where pushing `main` auto-deploys (Cloudflare Pages Git integration): the report must show `git log --oneline origin/main..main`; a bare `git push origin main` is never accepted as the proposed deploy command.
- Close each pane only after the output is verified (`close-worker.mjs`); keep it open only while a follow-up round is expected.

## Failure modes
- Command typed but not executed (pane shows the line at `PS ...>`): `terminal.write {key:"enter"}` as its own call; `runSeq` not growing is the proof the Enter stayed in the box.
- `run-idle` timeouts with no `π` footer: the launch line was never submitted.
- Worker asks a question: it should not use `ask` (see `report-contract.md`); an open dialog is answered with `answerKeys` (table above).
